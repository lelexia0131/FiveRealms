# FiveRealms Code Standard

状态：Architecture Baseline v1
适用范围：新增或实质修改的可维护 JavaScript；历史代码按触碰迁移，不要求一次性清仓。

## 1. 目标与执行原则

代码应让后续维护者无需追溯聊天记录就能确认职责、状态边界和不变量。规则按以下方式渐进执行：

1. 新函数和本次实质修改的函数必须符合本规范。
2. 新建、迁移或大幅重写的 AI 核心模块必须同时有模块头。
3. 未触碰的历史代码可以暂不迁移；`--all` 的历史欠债不得通过弱化门禁解决。
4. 注释解释“为什么”和边界，不复述语法，也不记录开发过程。

## 2. Function Header v1

### 2.1 必须覆盖的函数

以下新增或实质修改的可维护函数必须在声明正上方使用普通块注释：

- `function`、`async function` 和导出函数；
- 类构造器、普通方法、异步方法、getter、setter；
- 具名箭头函数和文件级 helper；
- 承载规则、状态转换或复用逻辑的测试 helper；
- 复杂匿名回调。此类回调应先提取成具名函数，再补函数头。

一行、显然且不承担独立业务语义的匿名 lambda 可以豁免，例如简单 `map` 投影或布尔 `filter`。一旦回调有多步控制流、状态写入、公式或错误恢复，就不再豁免。

### 2.2 固定格式

必须使用普通块注释 `/* ... */`，不得使用 JSDoc 的 `/** ... */`、`@param` 或 `@returns`。字段标题必须独占一行，标题后不得带冒号或正文；注释内部不得使用 `*` 前缀。字段顺序和名称固定如下：

```js
/*
功能
一句话说明该函数负责的业务结果。

调用方
列出直接调用者或稳定入口。

输入
参数的业务含义、单位或合法范围。

输出
返回值、异常或异步完成语义。

读取状态
读取的 GameState/VisibleState/BeliefState/SearchState/服务；没有则写“无”。

写入状态
明确写入对象与生命周期；纯函数写“无”。

调用函数
关键下游函数或外部权威；没有则写“无”。

边界与不变量
失败、取消、概率和对象身份等必须保持的条件。
*/
```

字段内容不能空置，也不能只写“同上”“见代码”。标题之间用一个空行分隔，使学生和维护者能清楚区分“字段名”与“解释”；字段正文可以按需要跨多行，但不得伪造新的标题。一个函数只写一个完整函数头；不要为每个参数机械扩写段落。

以下写法均不合法：

```js
/** 功能头不得使用 JSDoc。 */

/*
 * 功能
 * 星号前缀属于旧格式。
 */

/*
功能：标题和正文不得写在同一行。
*/
```

### 2.3 示例

```js
/*
功能
从 AI 可见状态生成当前角色的合法候选动作。

调用方
AIController.getLegalActions、AiPlanner 深层节点展开。

输入
过滤后的 SearchState 与行动者 ID。

输出
不含重复实体选择的候选动作数组。

读取状态
SearchState 玩家公开字段、次数槽和概率分支。

写入状态
无。

调用函数
RuleEngine 合法性镜像、Probability 分支工具。

边界与不变量
不得读取敌方真实手牌定义；终止节点只能返回空数组。
*/
function generateFromVisible(state, playerId) {
  // ...
}
```

## 3. Module Header v1

新建、迁移或大幅重写的 AI 核心模块必须在 import 之前声明：

```js
/*
模块职责
本模块唯一拥有的业务能力。

上游
允许依赖本模块的层或入口。

下游
本模块可依赖的层与权威服务。

状态边界
允许读取和写入的状态类型。

信息边界
公开信息、合法私有记忆、Belief，或明确禁止的数据。

架构约束
不得出现的依赖方向、回指或重复规则。
*/
```

模块头使用与函数头相同的无星号、无冒号、标题独占行规则。模块头不是文件目录说明。职责混合到无法准确填写时，应先拆分或在迁移计划中登记，不得用宽泛描述掩盖设计问题。

## 4. 内部注释

必须用 `//` 解释下列非显然逻辑：

- 公式、权重、缩放和魔法数字的单位与推导；
- 反直觉规则、概率状态转移和互斥分支；
- GameState、VisibleState、BeliefState、SearchState 与 Knowledge 的生命周期；
- 反事实世界、概率世界的配对方式；
- 同一张牌或同一资源不可重复消费的身份不变量；
- beam、frontier、prior、transition、residual 等搜索术语的精确定义；
- 隐藏信息为何合法、何时降级为分布；
- 性能近似、缓存边界、错误恢复与取消语义。

不要注释简单赋值、显然循环和普通 getter。禁止把以下开发历史写入正式源码：阶段编号、CASE 编号、代理名称、聊天上下文、“为了通过测试”、临时验收标记和只在当前版本成立的构建故事。

## 5. AI 分层约束

AI 代码除本规范外还必须遵守 `AI_ENGINE.md`：

- `search`、`simulation`、`value` 不得依赖 UI；
- Planner 不得通过 `game.aiController` 回取 ActionGenerator、Knowledge 或 Policy；依赖必须显式注入；
- 模拟器只能写 SearchState，不能写真实 GameState；
- 隐藏信息必须标记为 LEGAL OBSERVATION、MEMORY、BELIEF 或 ILLEGAL；ILLEGAL 读取不得进入生产决策；
- 规则权威、模拟镜像和派生模型必须区分，模拟镜像不得伪装为规则权威；
- 价值字段必须有唯一 owner，不能在 prior、state delta、response ledger 和 frontier residual 间重复计分。

## 6. 自动检查

默认门禁：

```powershell
npm run check:code-quality -- --changed
```

检查器只使用 Node.js 标准库。`--changed` 聚焦相对 Git 基线发生实质变更的生产 JavaScript 函数；`--all` 用于盘点历史欠债，不是当前阶段的零告警承诺；`--self-test` 验证合法无星号格式以及缺字段、旧星号格式、JSDoc、同一行标题、模块头和架构边界失败夹具。错误必须包含文件、函数、位置和具体格式问题。

Architecture Guard 目前只实施能够低误报判断的边界：目标分层目录对 UI 的非法 import、State 对编排层的逆向 import，以及 `js/ai/**` 任意文件中的 `game.aiController`/`this.game.aiController` 服务定位器回指。Controller 之外的 core 上游允许通过稳定门面调用 `game.aiController`，但不得直接取其子组件。后续迁移阶段再基于稳定目录和依赖契约扩展；禁止用模块名黑名单假装完成架构检查。

## 7. 评审清单

- 每条改动都能追溯到任务目标；
- 新增/修改函数具有完整 Function Header v1；
- 新建/迁移 AI 模块具有 Module Header v1；
- 状态读写、隐藏信息和概率边界准确；
- 价值没有重复记账，模拟没有写真实状态；
- 相关测试、完整测试（适用时）、build 一致性（适用时）、质量门禁和 `git diff --check` 均有实际证据。
